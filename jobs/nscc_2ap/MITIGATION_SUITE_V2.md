# Full English mitigation suite: all three models

Run from the repository root on ASPIRE2A+ after `git pull origin main`:

```bash
bash jobs/nscc_2ap/submit_mitigation_suite.sh
```

This submits **39 one-GPU PBS jobs and 99,876 outputs**, not 39 simultaneous allocations. Actual concurrency depends on queue/project limits. Every job uses the existing `normal` submission queue, project 13014407, a 24-hour limit and the configured conda/cache paths. It does not install libraries, launch smoke tests or download models. All three model snapshots must already be cached, as for the completed benchmark runs. Prepared inputs are included in Git, so no data-preparation or translation job is needed to run this frozen suite.

To inspect the plan without submitting anything:

```bash
python scripts/submit_mitigation_suite.py
```

To submit only one dataset or model:

```bash
bash jobs/nscc_2ap/submit_mitigation_suite.sh --dataset ragtruth
bash jobs/nscc_2ap/submit_mitigation_suite.sh --model llama3.1-8b
```

Do not issue these in addition to the all-suite command unless you intend to resume; the submission ledger skips queued/running and completed jobs. Do not delete that ledger. The script stops if prior job status is unclear.

## What each comparison establishes

- HaluEval generates new answers against the supplied knowledge. Reference answers never enter prompts. The original grounded/hallucinated candidate detection scores are not labels for these new generations.
- RAGTruth generates new QA answers, summaries or business descriptions from all 450 unique source tasks represented in its prepared test split. Its 2,675 existing annotated responses are multiple old outputs per source, not 2,675 independent prompts. Their original span labels cannot label the newly generated text. QA questions and passages are separated; summary word limits are retained. Original prompts containing evidence are not copied into the no-evidence CAD branch.
- TruthfulQA uses all 817 documents recovered from the saved official MC1 output, rather than the local older 790-row CSV. Choice order is deterministically shuffled once per question, identically across models and conditions. Prompted choice accuracy is directly scoreable but **is not official likelihood-based MC1/MC2**. Keep the earlier official scores as a separate result table.
- Mu-SHROOM compares closed-book hallucination-span detection prompts. The candidate and question are supplied, but reference URLs, gold spans and reference facts are not. This tests **detection quality**, not reduction of hallucinations generated by these models. Character metrics, invalid rates and positive-only IoU are reported separately from generation mitigation.

CAD is only defined for source-grounded tasks. It uses alpha=1.0 fixed in advance, separate context/no-context caches, identical generated prefixes, and no candidate filter. Raw contextual likelihood and normalized CAD probabilities are stored separately; neither represents factual correctness. All models/conditions have a total 2,048 generated-token budget, including reasoning or evidence. Raw means across languages/models are not calibrated correctness scores.

This is a new **v2** study. It does not overwrite or silently pool with the 150-question Qwen v1 run. V2 accepts repeated preface headings when there is exactly one final heading, a parsing rule chosen after observing v1 formatting issues. State this development history in the thesis. DeepSeek reasoning before `</think>` is excluded from final answers and final-token statistics; missing/ambiguous reasoning termination is invalid. Claim-checking prompts use CHECK:/FINAL:, and evidence-first uses EVIDENCE:/ANSWER:. Missing final sections, truncation, invalid choice numbers and invalid span JSON remain failures with explicit denominators.

The source-grounded v2 baseline prompt and budget differ from v1, so a fresh baseline is generated for every model. No improvement is assumed before scoring/annotation.

## Completion, resume and aggregation

HaluEval is split into ten deterministic 1,000-question shards per model. Other datasets use one shard per model. Jobs checkpoint every answer and stop gracefully between answers after 22 hours; this is not a prediction of runtime. A partial shard is marked incomplete and must be resumed. All immutable config/model/code/data fingerprints must match when resuming.

Results are under:

```
results/mitigation_suite_en_v2/DATASET/MODEL/shard_000/
```

Each shard contains predictions.jsonl, summary.json, run_metadata.json and checkpoint/. Keep all files. The submission ledger is results/mitigation_suite_en_v2/submissions.jsonl. Resubmitting the suite skips completed and active jobs and resumes remaining work. A hard scheduler kill can leave writer.lock: verify the original job is no longer running before removing only that stale lock. Never delete checkpoints to bypass a provenance mismatch.

After every shard for a model/dataset finishes:

```bash
python scripts/aggregate_mitigation_suite.py --dataset halueval_qa --model qwen2.5-7b
```

Repeat for each model/dataset. Aggregation refuses incomplete, duplicated or inconsistent shards and recomputes metrics from rows rather than averaging shard metrics. Return the results directory, including metadata and predictions; checkpoints can be archived separately if transfer size is a problem. Factuality statistics for newly generated HaluEval/RAGTruth answers remain pending annotation. More generations do not remove that validation requirement.

## HalluLens excluded

HalluLens is excluded at the user's request. This suite covers the other four datasets only. Hindi and other non-English comparisons remain deferred.

## Provenance and checks

Dataset licenses and attribution remain those of HaluEval, RAGTruth, TruthfulQA and Mu-SHROOM. The manifest records source-file hashes and newline-independent prepared-content hashes. The original benchmark URLs are in configs/benchmark_suite.thesis.json; TruthfulQA official documents were recovered from the supplied official-harness results archive.

Validation performed locally uses CPU-only synthetic decoder/scoring checks, prompt-leakage checks, complete source counts/hashes, and PBS/shell syntax checks. No pretrained-model smoke run or expanded H100 experiment has been executed locally. Runtime, actual cluster acceptance and expanded model behavior remain to be observed.
